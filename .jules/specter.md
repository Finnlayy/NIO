# SPECTER'S JOURNAL — CRITICAL LEARNINGS ONLY

## 2026-09-06 - NIO frontend profile: where the render waste actually lives
**Learning:** The NIO ops grid (`frontend/src/ops`) is a zustand-driven widget canvas. The live telemetry tick (`ops/page.tsx`, 2.2 s) calls `mergeData` → new `widgets` array → `GridCanvas` re-renders → **every** `WidgetFrame` re-renders (no memo, three inline arrow-closure props, and `children={renderWidget(widget)}` is a fresh element each render). Each frame carries a heavy subtree (SVG sparklines, 12-bin heatmaps, 28-item ticker tapes). Drag reorder is the second storm: `draggingId` state flips all frames. Second finding: `McpConsole` subscribes to the whole `mcpLog` and re-renders up to 60 rows + `JSON.stringify` per row on every event — even while closed. Third: `Sparkline` (bits.tsx) uses a **document-scoped SVG id** `spark-${color}` for its gradient — two same-color sparklines on one page share one id (style-scope leak across widget boundaries).
**Action:** Cycle 1: memoize the heavy widget content + stable `useCallback` drag handlers + extract pure `DragSession`. Cycle 2: split `McpConsole` into a shell (subscribes to `consoleOpen` only) + `McpConsoleLog` (subscribes to `mcpLog`), memoize `LogRow`, coalesce bottom-scroll via rAF. Cycle 3: `useId()` for the Sparkline gradient.

## 2026-09-06 - framer-motion `layout` measurement is per-component — memo must respect the boundary
**Learning:** Verified in framer-motion v12 source (`MeasureLayoutWithContext`): layout re-measurement happens in `getSnapshotBeforeUpdate` → `projection.willUpdate()` → `isLayoutDirty = true`, and `ProjectionNode.updateLayout()` **early-returns unless the node is dirty**. A `motion.section layout` inside a `React.memo` boundary that skips its render will NOT re-measure after a grid reorder → shifted widgets jump instead of spring-animating. Wrapping the whole `WidgetFrame` (including its `motion.section`) in `React.memo` would break the drag-reorder animation UX.
**Action:** Keep the thin `motion.section` shell un-memoized (it is cheap: header + controls) and memoize the heavy content below it (`WidgetFrameContent`). The shell re-render is the price of correct layout projection; the win is skipping the heavy data-viz subtrees.

## 2026-09-06 - Test strategy without adding dependencies (package.json is frozen)
**Learning:** The frontend has no test framework and `package.json`/`tsconfig.json` are frozen. Solution: a zero-dependency harness (`frontend/scripts/ui-test.mjs`) that (1) copies the modules under test to `.test-build/` with `@/` alias imports rewritten to relative paths, (2) compiles them with the project's own `tsc` as CommonJS, (3) runs Node's built-in `node --test` on plain-JS tests that SSR-render with `react-dom/server` (no DOM needed) plus unit-test the pure modules. Re-render *counts* can't be measured without a client DOM; instead the tests verify the skip contract directly: memo boundaries present + props shallow-stable across unrelated store updates (exactly what `React.memo`'s default comparator needs to bail out).
**Action:** Reuse the harness for all cycles; keep tests in `frontend/src/ops/__tests__/`, output in gitignored `.test-build/`.

## 2026-09-06 - Cycle 1 delta: live-tick churn 10/10 → 1/10 widget frames
**Learning:** Measured with `churn-report.js` (fake-dispatcher direct component calls, real zustand store, real handlers): before, one telemetry tick churned props on **all 10 frames** (1065 DOM nodes re-diffed); after the memoized `WidgetFrameContent` + `useCallback` drag handlers, exactly **1 of 10** (the ticked Envelope Chart). DOM output byte-identical (budget guard 1065 holds). Drag-start churns only the dragged frame; drag-enter reorders churn only shifted indices — and the layout springs survive because the `motion.section` shell is deliberately un-memoized.
**Action:** Re-run `node .test-build/__tests__/churn-report.js` after any change to GridCanvas/WidgetFrame; a tick must never churn more frames than widgets whose data actually changed.

## 2026-09-06 - Headless re-render testing on React 19 CJS (dispatcher injection)
**Learning:** Two traps when simulating client re-renders without a DOM: (1) `react-dom/server` always reads zustand's `getServerSnapshot` (initial state) — a seeded store is INVISIBLE to SSR; stateful view tests must call the component function directly instead. (2) React 19 CJS exposes the dispatcher slot as `React.__CLIENT_INTERNALS_DO_NOT_USE_OR_WARN_USERS_THEY_CANNOT_UPGRADE.H` (the old `__SECRET_INTERNALS...` is gone). A fake dispatcher with persistent hook slots (useState/useRef/useCallback/useMemo keyed by call index, `useSyncExternalStore` → live `getSnapshot()`) makes `Component()` calls behave like real re-renders — including `setDraggingId` updates flowing into the next render. Every hook (even `useDebugValue`) must consume a slot or the slot map silently shifts. Bonus traps found the hard way: JSX `{list.map(...)}` children are NESTED arrays (tree walkers must recurse into them), React coerces numeric `key` to string, and React escapes `&`/`"` in both text and attribute values.
**Action:** `helpers.js` (mount/collectByType/hasText/lastSnapshots) is the reusable kit; `lastSnapshots` lets a test AUDIT which store slices a component subscribes to (proves the closed-console has zero log subscriptions).

## 2026-09-06 - Cycle 2 delta: closed console now does zero work per MCP event
**Learning:** Before, every MCP event re-rendered `McpConsole` (whole 60-row log + `JSON.stringify` per row) and queued a smooth `scrollIntoView` — even while the console was closed. After the shell/log split: closed → zero re-renders (verified via snapshot audit: no `mcpLog` subscription while unmounted); open → exactly one row re-renders per event (memoized `LogRow`, events are immutable), count leaf re-renders only while below the 60-cap, and `LogScroller` collapses same-frame scroll requests into one. The `motion.div` stays a DIRECT child of `AnimatePresence` so the slide exit animation is preserved (custom components one level down would have risked the exit).
**Action:** When splitting a panel, keep the AnimatePresence child a bare motion component; push subscriptions to leaves that mount only while open.

## 2026-09-06 - Cycle 3 delta: SVG id namespace is document-wide — scope it with useId
**Learning:** `Sparkline` keyed its `<linearGradient id>` off the *color* → every same-color sparkline on the page shared one document id (style-scope leak across widget boundaries; and a broken `url(#...)` fill if the first instance unmounts while a same-color sibling is still mounted). `useId()` fixes it: unique per instance, stable across re-renders AND hydration (so the browser's cached paint reference for `url(#…)` survives re-renders). Verified: two same-color charts → two distinct gradient ids, each `fill` resolving to its own def.
**Action:** Never derive SVG `id`/`url(#…)` pairs from shared values (color, kind, index); always scope per instance. The `sparkline.test.js` "distinct gradients" assertion fails against the old code — keep it as the guard.
