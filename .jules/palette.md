## 2024-03-20 - Adding Accessible Context to Disabled Controls
**Learning:** Disabled `<button>` elements prevent mouse/keyboard events (like hover for native `title` tooltips or focusing via tab), making their state opaque to screen reader users and leaving sighted users guessing *why* it's disabled. Additionally, log streams that update dynamically do not announce changes natively without proper ARIA regions.
**Action:** Always wrap dynamically disabled buttons in a generic `<div>` wrapper with an explanatory `title` (and conditionally set `tabIndex={0}` or use ARIA patterns if deeper context is needed) so the underlying reason for the disabled state is passed through natively to all users. Additionally, always ensure dynamically updating log feeds are wrapped with `role="log"` and `aria-live="polite"` so screen readers can announce new items.
