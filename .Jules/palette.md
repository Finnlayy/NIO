## 2026-09-12 - Keyboard Shortcut and Modal Close Accessibility
**Learning:** We realized that global keyboard shortcuts in the dashboard were hijacking inputs for users trying to use forms (specifically in elements with `isContentEditable` set). Additionally, drawer/modal components were missing standard Escape key listeners, forcing users to click close buttons or the backdrop, thus limiting keyboard navigation.
**Action:** Always verify `document.activeElement?.isContentEditable` alongside input and textarea tags when writing custom keyboard shortcut hooks. Furthermore, all overlay menus must pair with an `Escape` key close listener to support non-mouse accessibility.
## 2026-10-22 - Improved Accessibility of Disabled Submit Button in Task Console
**Learning:** In the `TaskConsole` component, the main action button (run task) used the native `disabled` attribute when there's no task text or it's currently running. Native disabled buttons remove the element from the keyboard tab order and make hover tooltips inaccessible to keyboard users and screen readers, which is problematic since the tooltip ("Enter a task description to run") contains important guidance for the user. When converting to `aria-disabled="true"` to fix this, it's NOT necessary to wrap the button in a focusable element (`tabIndex={0}`) when disabled, as removing the native disabled attribute inherently makes the button focusable again. Wrapping it actually causes a double tab-stop bug.

**Action:** Replaced the native `disabled` attribute on the primary "Run through Neural Core" button with `aria-disabled="true"` to make it focusable so screen readers can access its `title` tooltip. Manually guarded the `onClick` handler to prevent execution when logically disabled, and updated `globals.css` to respect the `aria-disabled="true"` state for styling (maintaining the visual disabled state and avoiding hover effects).
