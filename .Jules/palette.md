## 2026-09-12 - Keyboard Shortcut and Modal Close Accessibility
**Learning:** We realized that global keyboard shortcuts in the dashboard were hijacking inputs for users trying to use forms (specifically in elements with `isContentEditable` set). Additionally, drawer/modal components were missing standard Escape key listeners, forcing users to click close buttons or the backdrop, thus limiting keyboard navigation.
**Action:** Always verify `document.activeElement?.isContentEditable` alongside input and textarea tags when writing custom keyboard shortcut hooks. Furthermore, all overlay menus must pair with an `Escape` key close listener to support non-mouse accessibility.
## 2024-10-18 - [Tooltip Explanations for Disabled Buttons]
**Learning:** Native HTML `disabled` attributes remove elements from the tab order and swallow pointer events, which entirely prevents keyboard and mouse users from accessing `title` tooltips that explain *why* the button is disabled (e.g. "Enter a task description"). This causes a confusing dead-end experience.
**Action:** When conditionally disabling key action buttons, prefer adding `aria-disabled="true"` combined with a descriptive `title` tooltip and manually guarding the `onClick` handler in JavaScript. Ensure the global CSS properly maps `:disabled` pseudo-class styles to `[aria-disabled="true"]` so hover feedback is still correctly suppressed.
