## 2026-09-12 - Keyboard Shortcut and Modal Close Accessibility
**Learning:** We realized that global keyboard shortcuts in the dashboard were hijacking inputs for users trying to use forms (specifically in elements with `isContentEditable` set). Additionally, drawer/modal components were missing standard Escape key listeners, forcing users to click close buttons or the backdrop, thus limiting keyboard navigation.
**Action:** Always verify `document.activeElement?.isContentEditable` alongside input and textarea tags when writing custom keyboard shortcut hooks. Furthermore, all overlay menus must pair with an `Escape` key close listener to support non-mouse accessibility.
## 2023-10-24 - Accessible Disabled States and Dynamic Feeds
**Learning:** Using native `:disabled` removes elements from the tab order and prevents hover tooltips from working. Switching to `aria-disabled="true"` preserves focusability and tooltip functionality, but requires guarding the `onClick` handler and updating CSS to match the native `:disabled` styles (e.g., `:not([aria-disabled="true"])` for hover states). Additionally, lists that update dynamically (like the activity feed) must be explicitly marked with `role="log"` and `aria-live="polite"` so screen readers can announce the updates smoothly.
**Action:** Enforce `aria-disabled="true"` instead of native `disabled` for interactive buttons that benefit from focusable tooltips or explanations. When doing so, always guard the event handler and apply the necessary `[aria-disabled="true"]` styles. Always wrap dynamically updating lists in `role="log"` with `aria-live="polite"`.
