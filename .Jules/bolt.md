## 2024-09-11 - Next.js Global Shortcut Focus Collisions
**Learning:** Global hotkeys attached to `window` using `keydown` events will indiscriminately capture user typing if the user is inside a form input (`<input>`, `<textarea>`), creating significant operational friction and context loss when shortcuts like `/` or `k` are mapped. Additionally, modifier keys diverge between Mac (Cmd / `metaKey`) and Windows/Linux (Ctrl / `ctrlKey`).
**Action:** Always implement a manual check for `document.activeElement?.tagName` (checking for `input` or `textarea`) inside the event listener to gracefully return early if the user is typing, effectively suppressing the hotkey. Always handle OS divergence by checking `(e.metaKey || e.ctrlKey)`. Combine with a native `Escape` listener scoped to the specific input ref to allow the user to blur without using the mouse.

## 2024-09-14 - Escape-to-Reset Uniform Workflow Cascade
**Learning:** In complex dashboards with global shortcuts and persistent focus states (like textareas for task inputs or search fields), relying only on explicit mouse clicks to clear focus or reset UI state creates operational friction. Trapped focus in form fields prevents other global shortcuts from firing.
**Action:** Implement a two-stage `Escape` cascade pattern. First, intercept `Escape` globally and check if the user is in an active input context (`input`, `textarea`, `isContentEditable`); if so, perform a safe `blur()` to free the keyboard without losing data. Second, if `Escape` is pressed when no input is focused, map it to the application's primary "reset" or "master view" state. Ensure clear `<kbd>` visual badges are added for these cascaded actions.
