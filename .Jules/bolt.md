## 2024-09-25 - Centralized Keyboard Handlers & Modal Ergonomics
**Learning:** Adding local keydown listeners for Escape inside modals bypasses global input guards and can indiscriminately steal keystrokes. Modals also lack inherent keyboard traversability without proper roles and autofocus targets.
**Action:** Remove redundant local Escape listeners in favor of a centralized `opsHotkey` global handler with `isTypingTarget` guard explicitly wiring the `close-panels` action. Ensure all modals use `role="dialog"`, `aria-modal="true"`, and `autoFocus` on the primary dismiss element for accessibility and speed.
## 2024-09-25 - Ergonomic Pattern for Escape Hotkey with Localized Menus
**Learning:** Adding local `keydown` event listeners for the `Escape` key inside dropdown menus can cause widespread event collision, stealing keystrokes indiscriminately and bypassing global input guards like `isTypingTarget`. Relying on local component state (`useState`) for menus makes it difficult for a centralized hotkey handler to close them.
**Action:** Lift the open-state of localized dropdown menus into a global store (e.g., Zustand `activeMenuId`). Use strict equality selectors (e.g., `s.activeMenuId === widget.id`) to prevent unnecessary re-renders. Handle the `close-panels` action in the centralized global hotkey handler (guarded by `isTypingTarget`) to clear the active menu cleanly.
