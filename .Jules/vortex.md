## 2024-05-24 - Hardware-Accelerated Progress Bars & Transitions
**Learning:** Progress bars (e.g., in NewsSentiment, TechnicalGauge, PatternScanner, CompositeRankings) were animating the `width` property natively, and widget collapse animations were animating the `height` property. This triggered synchronous CPU layout calculations (layout thrashing) on every frame during high-frequency telemetry ticks. CSS transitions for `border-color`, `background-color`, and `box-shadow` were also triggering unnecessary repaints.
**Action:** Refactored all progress bars to use hardware-accelerated composite layers via `transform: scaleX(...)` with `transformOrigin: left` instead of `width`. Stripped all non-composite `transition` and `transition-colors` classes from components and `globals.css`. Removed `height` transitions from Framer Motion widget collapse.
