
## 2026-09-20 - [Graphics / Rendering Insight]
**Learning:** `transition-all` triggers heavy CPU reflow and layout-thrashing on every frame, and animating properties like `width` causes layout invalidation.
**Action:** Replaced `transition-all` with `transition-colors` in FilterBar and page ops. Replaced `width` animations in `NewsSentiment` and `PatternScanner` horizontal progress bars with `transform: scaleX(...)` and `transformOrigin: left` to ensure pure composite-layer animation running on GPU.
\n## 2026-09-20 - [Graphics / Rendering Insight]\n**Learning:** Animating `width` directly triggers heavy CPU reflow and layout thrashing, and while replacing it with `transform: scaleX(...)` solves the CPU issue, it causes visual distortion (squishing) on elements with `border-radius` (rounded corners).\n**Action:** Replaced layout-thrashing `width` animations with GPU-accelerated `clip-path: inset(...)`. This ensures pure composite-layer animation running on GPU without causing layout recalculation or squishing the borders, which is crucial for widgets like `CompositeRankings`, `TechnicalGauge` and `KeyLevelsTable`.
